## 1. 最后一次组合验证

配置：`configs/train/p6_check/muon_qknorm.yaml`。在 P5b Muon 配置上仅增加 QK-Norm，保留 z-loss、seed 0、v1 数据和 790,102,016 tokens。新目录 `runs/p6_check/muon_qknorm` 避免覆盖旧实验。

用完整的 3014 步而非只跑几百步，才能与第二轮最终 loss 比较。按第二轮每步约 1.3 秒估计纯训练约 65–70 分钟，含评测存档预计 75–90 分钟，不含排队；申请 1 小时 50 分钟，主动训练预算 95 分钟。中途退出则从完整 checkpoint 续跑。

**推送并在 Rangpur 更新仓库后，登录节点、仓库根目录执行：**

```bash
mkdir -p logs
sbatch --time=01:50:00 --export=ALL,CONFIG=configs/train/p6_check/muon_qknorm.yaml,MAX_MINUTES=95 scripts/rangpur/train.sbatch
```

观察最终 3014 步 eval、退出原因与权重；同时检查早期梯度（Muon 第二轮 step 40 出现过 8.35）。对比 Muon 3.3048、QK-Norm+z-loss 3.3087 和基线均值 3.3373。单次组合结果不能代替多种子或 250M 验收；不能把中途 loss 与其他 run 最终 loss 比较。

## 3. Rangpur 备份清单

在所有相关作业退出、目录停止写入后建立清单。大文件扫描、SHA256、打包均放 CPU 作业；不在 home 再造一份大型 tar 导致配额翻倍。

| 内容 | 保存策略 |

| 临时目录 | 退出作业前取回未同步成果；作业结束后的临时目录不可依赖 |

## 4. 清理门槛

1. 本地清单与远端清单逐文件核对路径、大小、SHA256，确保缺失数为零。对比发生在文件停止写入之后。
2. 在本地逐个加载最终权重，按对应模型配置严格加载 state_dict，做短前向检查；需续训的 checkpoint 另外确认优化器、数据状态和随机数完整。
3. 指标可解析、报告可复现、代码版本可定位；只看到 scp 成功或 final.pt 文件名不算完成。
4. 上述通过后，CPU 作业内清理本项目数据、产物、缓存和专属 venv，释放空间。删除前解析并核对实际目标路径，只处理本项目；保留 `~/miniconda3` 和其他课程/项目目录。
5. 记录清理前后 `df -h "$HOME"`；后续 P7/P8 如需 Rangpur，再按需上传必要文件。

## 5. 学习重点

组合验证回答的是“两个独立有效改动放在一起是否仍有效”；备份验证回答的是“离开原计算环境后成果能否恢复”。两者都需要实际运行证据。把最终权重和优化器 checkpoint 区分开，才能判断文件足够用于推理，还是足够继续训练。
