# 评测方案

**核心原则：不报无意义的分数。** 250M 模型在 MMLU、GSM8K、HumanEval 上基本是随机水平，报出来只会显得不懂行。挑真正有区分度的任务，并如实说明哪些能力这个规模不具备。

---

## 一、任务选择

用 `EleutherAI/lm-evaluation-harness`。

### 有区分度（必报）

| 任务 | 类型 | 随机基线 | 250M 合理区间 | 说明 |
|---|---|---|---|---|
| **HellaSwag** | 常识续写 | 25% | 33–38% | 小模型最主要的信号，对预训练质量敏感 |
| **PIQA** | 物理常识 | 50% | 64–69% | |
| **ARC-easy** | 科学问答 | 25% | 45–54% | |
| **ARC-challenge** | 科学问答 | 25% | 25–29% | 250M 上基本没有区分度 |
| **WinoGrande** | 指代消解 | 50% | 50–54% | 接近随机，谨慎解读 |
| **LAMBADA** | 长程依赖补全 | 0% | 32–45% | 直接反映建模能力，推荐 |
| **C-Eval / CMMLU** | 中文知识 | 25% | 25–28% | 只有加了足够中文数据才会高于随机 |
| **val perplexity** | 分子集报 | — | — | **最诚实的指标**，务必分中/英/代码/数学分别报 |

### 无区分度（不报，或明确标注"接近随机"）

MMLU、GSM8K、HumanEval、BBH、MATH、TruthfulQA —— 这些需要 3B+ 才开始有意义。**如果你的 250M 在 MMLU 上超过 28%，先怀疑数据污染，而不是庆祝。**

### 后训练模型额外看

- **IFEval**（指令遵循格式）— SFT 后应有明显提升
- **MT-Bench 单轮**（用更强模型打分）— 参考性有限，但能看出对话流畅度
- **人工评测**：固定 50 条 prompt，SFT 前后并排对比，自己打分。**这比任何自动指标都有用。**

## 二、对照基线

同条件（同 harness 版本、同 few-shot 设置）跑这几个模型作对照：

| 模型 | 参数 | 训练 token | 为什么选它 |
|---|---|---|---|
| **Pythia-160M** | 160M | 300B | 比你小但 token 多 30 倍，最能看出"数据量 vs 参数量"的取舍 |
| **GPT-2 (124M)** | 124M | 10B | token 量最接近，历史参照 |
| **Pythia-410M** | 410M | 300B | 比你大，看差距有多大 |
| **SmolLM2-360M** | 360M | 4T | 现代小模型 SOTA，训练 token 是你的 420 倍 |
| **Qwen2.5-0.5B** | 494M | 18T | 中文强，作为中文能力的上界参照 |

**期望结果**：明显超过 GPT-2 124M（架构现代、数据更好），与 Pythia-160M 相当或略优，明显不如 Pythia-410M / SmolLM2-360M / Qwen2.5-0.5B。

**这是完全合理的**——它们用了几十到几百倍的 token。**在报告里把这个差距归因清楚（token 数 / 参数量 / 数据质量 / 退火配方），比拿到高分更有价值。** 你手上正好有缩放律曲线可以支撑这个归因，这是大多数复现项目给不出的东西。

## 三、评测纪律

1. **去污染在前**（见 [05-data.md](05-data.md)）。没做去污染的分数不要报。
2. **固定 harness 版本和 commit hash**，写进报告。不同版本的 prompt 模板不一样，分数不可比。
3. **统一 few-shot 设置**，通常 0-shot（base 模型）或 5-shot，别混着报。
4. **对照模型自己跑一遍**，不要抄别人论文里的数字——设置不同就没有可比性。
5. **报置信区间或多次采样的方差**，尤其是接近随机基线的任务。
6. **中间 checkpoint 也评一遍**（每 2000 步 ≈ 1B tokens 一个点，共 9 个），画出能力随训练量的增长曲线。这条曲线是报告里最有信息量的图之一。

## 四、定性分析（别跳过）

自动指标之外，固定一组 prompt，对每个 checkpoint 生成并保存：

```
1. 事实补全：  "The capital of France is"
2. 中文补全：  "中国的首都是"
3. 常识推理：  "If I drop a glass on the floor, it will"
4. 代码：      "def fibonacci(n):"
5. 数学：      "12 * 13 = "
6. 长程一致性： 给 3 段故事开头，看能否续写不跑题
7. 重复检测：   贪心解码 500 token，看会不会退化成循环
```

把不同 checkpoint 的输出并排放进报告附录——**读者从这里能看到的东西，比看 loss 曲线多得多**。

---

## 五、报告里怎么写"做不到什么"

这部分是加分项，不是减分项。老实列出来：

- 多步数学推理 —— 基本不行
- 长文档事实一致性 —— 会自相矛盾
- 事实准确性 —— 会自信地编造
- 长上下文利用 —— 4096 窗口内后半段的信息利用率低
- 事实知识 —— 250M 装不下多少世界知识，这是规模的硬限制
- 中文成语/古文 —— 数据覆盖不足

并说明**你判断这是规模限制还是配方问题**，以及如果给你 10 倍算力会先改什么。
