# 算力、时间与成本

---

## 一、先把账算清楚

**训练总 FLOPs**：

```
C = (6·N + 12·L·T·d) · D
     N = 非嵌入参数量        D = 训练 token 数
     L = 层数  T = 序列长度  d = d_model
     6  = 前向 2 + 反向 4
     12·L·T·d = 注意力打分部分（常被忽略，序列一长占比不小，漏掉会低估耗时）
```

主线 250M：`N = 2.029e8`，`L=18`，`T=2048`，`d=1024`，`D = 9.437e9` →

```
每 token FLOPs = 6×2.029e8 + 12×18×2048×1024 = 1.217e9 + 4.53e8 = 1.671e9
C              = 1.671e9 × 9.437e9 = 1.577e19 FLOPs
```

注意力那一项占 **27%**。模型越小占比越大（30M 模型上是 50%），只用 `6ND` 会严重低估小模型的耗时。

9.437B tokens ≈ **40 tokens/param**，是 Chinchilla 最优（20）的 2 倍，属于适度 over-train。

**换算成时间**：`时间 = C / (GPU数 × 峰值FLOPS × MFU)`

MFU（算力利用率）参考值：

| 情形 | MFU |
|---|---|
| 第一次跑，没调优 | 15–25% |
| 单卡 + 常规调优 | 30–40% |
| 8 卡跑**小模型**（本项目 P6） | **20–28%** |
| 8 卡跑大模型 + 深度优化 | 45–60% |

**小模型在多卡上 MFU 天然偏低** —— 单卡算力太强、模型太小，通信和边角开销占比上升。所以下面 8 卡按 25%、单卡按 30% 估。

## 四、性价比：每美元买到多少算力

单价便宜 ≠ 划算。把 MFU 算进去，看**每美元买到多少有效 FLOPs**：

| 硬件 | 单价/卡/时 | 有效算力（含 MFU） | **FLOPs / 美元** |
|---|---|---|---|
| ★ **H100 竞价** | ~$1.5 | 3.96e14 | **9.5e17** |
| RTX 4090（AutoDL ¥2.2） | $0.31 | 5.78e13 | 6.7e17 |
| L40S | ~$0.9 | 1.45e14 | 5.8e17 |
| H100 按需 | ~$2.5 | 3.96e14 | 5.7e17 |
| A100 80G（AutoDL ¥8） | $1.13 | 1.31e14 | 4.2e17 |

**反直觉但重要的结论：租 4090 不比 H100 竞价划算。** 4090 便宜在单价，每美元算力反而低 30%，而且 wall-clock 慢得多（250M×9.44B：8×H100 2.2 小时 vs 单卡 4090 3.5 天）。

消费级卡的正确用途是 **P0–P4 的调试阶段**——那时你要的是"随时能开、开着不心疼、想改就改"，不是吞吐。你本地那张 4070 Ti SUPER 正好胜任，且免费。

**P5 用单卡 H100 竞价，P6 用 8×H100 竞价。**

### 三个把成本压下来的做法

**1. 缩放律第 4 个点用 WSD 分叉免费拿。**
P6 训练到 step 9021（= 4.73B tokens = 20 tokens/param）时，分叉出一支做 900 步衰减到 0，得到一个与 30M/60M/120M 可比的 250M 数据点。**$1.4 而不是重训一次的 $11。**

这正是文档里选 WSD 而非 cosine 的理由在实际中兑现：稳定段 LR 恒定，可以在任意点分叉做退火，不用重训。cosine 一旦定了总步数就锁死，拿不到这个便宜。

> 注意：**不能直接拿 P6 在 4.73B 处的中间 checkpoint 当作这个点**。那时 LR 还停在稳定段没衰减，loss 明显高于一个真正训练到 4.73B 就收尾的模型，两者不可比。必须真的做那段衰减。

**2. 消融在 60M 上跑**，6 组共 57 分钟、$1.4。进阶：挑 2 组在 120M 上复跑，看效应是放大还是消失——这比单点消融有说服力得多。

**3. 单卡 / 8 卡分工。** 所有小实验用单卡 H100 竞价（$1.5/h，无需 DDP 调试）；只有 P6 用 8 卡。

### 本地 GPU 的定位

P0–P4 全部在本地 RTX 4070 Ti SUPER 上做，**零成本**。调试是短时的（几分钟一轮），不需要长时间占用机器。

但本地卡**只用于验证正确性，不用于测性能**：本地测到的 MFU 推不出 H100 上的 MFU（见 [06-training-recipe.md](06-training-recipe.md) 的跨硬件纪律）。250M 在本地跑完整训练要 8 天，不现实。

### 关键认知

**算力买的是模型质量，不是学习收益。**

P1–P5 全部内容——分词器、数据管线、架构实现、数值对齐、训练框架、缩放律、消融——加起来 **$5**，而这些才是项目主体。P6 的 $27 只是把一条已验证的流水线放大跑一次。

### 更省 / 更贵的选项

| 方案 | 全项目 | 代价 / 收益 |
|---|---|---|
| 120M × 4.0B | ≈ 33 AUD | 模型弱一档，流程完全一样 |
| ★ **250M × 9.44B** | **76 AUD** | 推荐 |
| 350M × 13.1B | ≈ 134 AUD | 超预算 |

### 用竞价实例的前提

竞价便宜 40–50%，但实例随时会被抢占。必须先做到：

1. 每 1000 步存 checkpoint 并**立即同步到对象存储**
2. 启动脚本能自动检测并从最新 checkpoint 恢复（含 dataloader 状态与 RNG）
3. 恢复后的 loss 曲线无跳变（P4 就要验证这一点）

这三条本来就是必做项，竞价只是让它们变成硬性要求。

## 六、租机操作要点

1. **先租最小的确认环境**：1 卡跑 30 分钟，确认 CUDA 版本、`torch.compile` 能过、数据能读、W&B 能连
2. **数据别放在实例本地盘** — 放对象存储（S3/R2/OSS），实例启动时拉取或直接流式读
3. **checkpoint 立刻同步到对象存储** — 实例被抢占是常态，不是意外
4. **用 tmux / nohup** — SSH 断了训练不能停
5. **算好再开机** — 开机前用公式估一遍时间，跑起来 10 分钟内核对实际吞吐与估算是否一致，差太多立刻停机排查
6. **监控要能推到手机** — W&B alert 或简单的 webhook，半夜炸了要能知道

## 七、MFU 上不去的排查顺序

1. dataloader 打不满 GPU（看 `step_time` 里的等待占比）→ 加 worker、预取、把数据放本地 NVMe
2. 没开 `torch.compile` 或被 graph break → `TORCH_LOGS=graph_breaks` 查
3. 没用 FlashAttention → 确认走了 `F.scaled_dot_product_attention` 的 flash 后端
4. batch 太小 → 增大 micro-batch 直到显存打满，再用梯度累积凑全局 batch
5. 维度不是 128 的倍数 → tensor core 对齐（本项目 d=1024、ffn=2816 已对齐）
6. 通信瓶颈（多卡）→ 检查是否 NVLink，`NCCL_DEBUG=INFO` 看拓扑
7. 梯度检查点开太多 → 250M 单卡显存够，能关就关（省 30% 时间）
