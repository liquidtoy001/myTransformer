# 算力、时间与成本

---

## 一、先把账算清楚

**训练总 FLOPs 的经验公式**：

```
C ≈ 6 · N · D
     N = 非嵌入参数量
     D = 训练 token 数
     6 = 前向 2 + 反向 4（每参数每 token 的乘加次数 × 2）
```

主线 500M：`N = 4.52e8`（非嵌入），`D = 2.5e10` →

```
C = 6 × 4.52e8 × 2.5e10 = 6.78e19 FLOPs
```

可选 1B：`N = 9.92e8`，`D = 2.5e10` →

```
C = 6 × 9.92e8 × 2.5e10 = 1.49e20 FLOPs      # 约为 500M 方案的 2.2 倍
```

500M 的 25B tokens ≈ **50 tokens/param**，是 Chinchilla 最优（20）的 2.5 倍，属于适度 over-train：模型明显比 Chinchilla 版好用，但不为最后那点边际收益付双倍钱。1B 的 25B tokens 只有 23 tokens/param，刚好在 Chinchilla 最优附近——**同样的 token 预算，参数越大越"吃不饱"**。

**换算成时间**：

```
时间 = C / (GPU数 × 峰值FLOPS × MFU)
```

MFU（Model FLOPs Utilization）是实际达到的算力利用率。参考值：

| 情形 | MFU |
|---|---|
| 第一次跑，没调优 | 15–25% |
| 常规调优（compile + flash-attn + 合理 batch） | 35–45% |
| 深度优化（大厂水平） | 50–60% |

**下面所有估算按 MFU=40% 计算，第一次跑请乘以 1.5–2。**

## 二、时间表

峰值算力（bf16 稠密，非稀疏）：H100 SXM ≈ 989 TFLOPS，A100 ≈ 312 TFLOPS，RTX 4090 ≈ 165 TFLOPS，L40S ≈ 362 TFLOPS。

### 500M 模型（主线）

| 硬件 | 10B tokens（Chinchilla） | **25B tokens（本项目目标）** | 51B tokens |
|---|---|---|---|
| 1× RTX 4090 24G | ~5.4 天 | ~13.5 天 | 不现实 |
| 4× RTX 4090 | ~33 小时 | ~82 小时 | ~7 天 |
| 1× A100 80G | ~2.4 天 | ~6 天 | ~12 天 |
| 1× H100 80G | ~19 小时 | ~2 天 | ~4 天 |
| 8× A100 40G | ~7.5 小时 | ~19 小时 | ~38 小时 |
| ★ **8× H100 80G** | **~2.4 小时** | **~5.9 小时** | **~12 小时** |
| TPU v4-32（TRC 免费） | ~4 小时 | ~10 小时 | ~20 小时 |

### 1B 模型（可选升级）

| 硬件 | 22B tokens（Chinchilla） | 25B tokens（推荐） | 50B tokens |
|---|---|---|---|
| 1× RTX 4090 24G | 不现实（且显存不够） | 不现实 | 不现实 |
| 1× H100 80G | ~3.8 天 | ~4.4 天 | ~9 天 |
| 8× A100 40G | ~36 小时 | ~41 小时 | ~3.5 天 |
| ★ **8× H100 80G** | **~11.5 小时** | **~13 小时** | **~26 小时** |

1B 的额外约束：单卡显存 26 GB 放不进 4090，必须上 ZeRO-2/FSDP 或 8-bit optimizer（见 [02-architecture.md](02-architecture.md) §1.4）。**这意味着 1B 不能在单卡上完整调试**，所有 bug 都得在多卡环境里查——这是 1B 真正的成本，比多花的那点钱大得多。

**建议**：先按 500M 走完 P0–P8 拿到完整报告，再用同一套代码跑 1B。这样 1B 那次训练是在一个已经验证过的流水线上跑，风险低得多，同时给缩放律曲线添上第 5 个点。

### 其它规模（做缩放律实验用）

## 四、性价比：每美元买到多少算力

单价便宜 ≠ 划算。把 MFU 算进去，看**每美元买到多少有效 FLOPs**：

| 硬件 | 单价/卡/时 | 有效算力（含 MFU） | **FLOPs / 美元** |
|---|---|---|---|
| ★ **H100 竞价** | ~$1.5 | 3.96e14 | **9.5e17** |
| RTX 4090（AutoDL ¥2.2） | $0.31 | 5.78e13 | 6.7e17 |
| L40S | ~$0.9 | 1.45e14 | 5.8e17 |
| H100 按需 | ~$2.5 | 3.96e14 | 5.7e17 |
| A100 80G（AutoDL ¥8） | $1.13 | 1.31e14 | 4.2e17 |

**反直觉但重要的结论：租 4090 不比 H100 竞价划算。** 4090 便宜在单价，每美元算力反而低 30%，而且 wall-clock 慢 7 倍（25B tokens：8×H100 六小时 vs 单卡 4090 十三天）。

4090 的正确用途是 **P0–P4 的调试阶段**——那时你要的是"随时能开、开着不心疼、想改就改"，不是吞吐。**P5–P6 一律用 8×H100 竞价。**

### 关键认知

**算力买的是模型质量，不是学习收益。**

P1–P5 的全部内容——分词器、数据管线、架构实现、数值对齐、训练框架、缩放律、消融——加起来不到 $50，而这些才是这个项目的主体。P6 只是把一条已经验证过的流水线放大跑一次。

所以**不要在 P6 之前省钱，也不要在 P6 上过度投入**。

### 用竞价实例的前提

竞价便宜 40–50%，但实例随时会被抢占。必须先做到：

1. 每 2000 步存 checkpoint 并**立即同步到对象存储**
2. 启动脚本能自动检测并从最新 checkpoint 恢复（含 dataloader 状态与 RNG）
3. 恢复后的 loss 曲线无跳变（P4 就要验证这一点）

这三条本来就是必做项，竞价只是让它们变成硬性要求。

## 六、租机操作要点

1. **先租最小的确认环境**：1 卡跑 30 分钟，确认 CUDA 版本、`torch.compile` 能过、数据能读、W&B 能连
2. **数据别放在实例本地盘** — 放对象存储（S3/R2/OSS），实例启动时拉取或直接流式读
3. **checkpoint 立刻同步到对象存储** — 实例被抢占是常态，不是意外
4. **用 tmux / nohup** — SSH 断了训练不能停
5. **算好再开机** — 开机前用公式估一遍时间，跑起来 10 分钟内核对实际吞吐与估算是否一致，差太多立刻停机排查
6. **监控要能推到手机** — W&B alert 或简单的 webhook，半夜炸了要能知道

## 七、MFU 上不去的排查顺序

1. dataloader 打不满 GPU（看 `step_time` 里的等待占比）→ 加 worker、预取、把数据放本地 NVMe
2. 没开 `torch.compile` 或被 graph break → `TORCH_LOGS=graph_breaks` 查
3. 没用 FlashAttention → 确认走了 `F.scaled_dot_product_attention` 的 flash 后端
4. batch 太小 → 增大 micro-batch 直到显存打满，再用梯度累积凑全局 batch
5. 维度不是 128 的倍数 → tensor core 对齐（本项目 d=1280、ffn=3456 已对齐）
6. 通信瓶颈（多卡）→ 检查是否 NVLink，`NCCL_DEBUG=INFO` 看拓扑
7. 梯度检查点开太多 → 500M 单卡显存够，能关就关（省 30% 时间）
